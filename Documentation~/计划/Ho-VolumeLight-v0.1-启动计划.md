# Ho-VolumeLight v0.1 启动计划

日期：2026-10-10。状态：v0.1 运行时/工具已实现；范围与用法见 [Ho-VolumeLight](../Ho-VolumeLight.md)，GPU 终验与原有环境回归见 [验证记录](Ho-VolumeLight-v0.1-验证记录.md)。

## 第一阶段目标

**使用场景已有太阳，一个 HoAtmosphere 大气区域，在多孔窗后得到可调、柔边、动态密度一致的 HD 丁达尔。** 地编不用逐窗添加灯或光柱；现有环境输入与 GI 行为保持原契约。

HoAtmosphere 是固定底层 Feature，统一发布 Environment 和 Medium 两个数据域；VolumeLight 只消费 Medium、相机深度与太阳照明/阴影，再绘制效果。

## 1. 先建立最小共享介质契约

新增 `Runtime/Atmosphere/Regions`，首版场景组件暂名 `HoAtmosphereRegion`。

第一阶段只支持解析 Box 范围，不先制作任意 Mesh 的 SDF 烘焙器。Box 的 signed distance 与边缘权重通过公共空间采样函数求值；以后 Sphere/Texture3D SDF 接同一入口。

用户需要调的最小参数：

- 区域大小、方向与边缘淡出。
- 连续介质密度、颜色、体积光参与权重。
- 可选的空间密度/噪声 Texture3D、世界尺度和风速。

纹理为空时使用均匀密度，不自动生成/导入资源。颗粒外观和粒子数量参数随颗粒功能落地再加入，不先显示无作用的设置。

建立 Registry 和不可变的本帧描述；确定 CPU/HLSL 对 region transform、bounds、软权重与纹理索引的解释。空间噪声用共同 world position/time；灯或观察相机不改变噪声坐标。

v0.1 首先验收一个区域；多区域混合与排除的序列化规则在增加多区域支持时明确，不让各消费者自行混合。

## 2. 从固定 HoAtmosphere 发布 Medium 输入

在 Feature 中添加独立的 Medium 准备/发布职责，现有环境 Cache 保持天空捕获语义。

- Medium 的 availability/revision 独立于 Environment；旧 `IsValid` 与 RTGI 环境接口先保持语义。
- 没有区域时发布明确空介质；缺失天空来源时仍可有有效区域。
- 区域改动只更新区域资源，不触发六面天空捕获或环境 GI 历史失效。
- 首版采用描述/矩阵/纹理引用，不建立常驻三维场 RT。
- 增加区域范围/密度调试入口，先验证输入再判断光束外观。

此时得到第一个可检查成果：移动大气盒子时，介质调试范围跟随；软边、颜色与噪声数据正确，天空捕获计数不变化。

## 3. 跑通太阳 HD 绘制

新增 `Runtime/VolumeLight` 和薄的 `HoVolumeLightRendererFeature`，先实现一个太阳区域 HD pass。

- 明确使用 HoURP 当前主 Directional Light，读取实际解析后的方向/颜色/强度；提供独立体积亮度倍率。
- 光源/工作距离与可见区间独立维护，由 SceneDepth 终止到不透明表面；SDF 在每个采样点控制区域内显示，保持完整光源范围。v0.1 全屏按工作距离积分，Bounds 发布给后续保守调度使用。
- 沿视线采样共享 Medium；按采样点 world position 查询太阳 cascade shadow atlas，保留窗格/树叶的几何遮挡。
- Screen Space Shadows 开启时仍读取世界空间光源阴影，不能使用可见表面的屏幕阴影作为空气遮挡。
- 输出线性 HDR 效果，首版采用稀薄加亮模型。侧边/边界淡出来自 Medium，接近物体时可见路径自然缩短。
- RenderGraph 明确声明 camera depth、主光阴影和大气资源读取；选用标准命名事件并遵守 Feature 顺序契约。

首版固定少量采样质量即可，先验证坐标与阴影一致性。低分辨率上采样、历史重投影、全局 froxel、atlas 优化在实际性能需求出现后决定。

太阳直接复用现有 URP 主光阴影，因此这个最小闭环不需要先实现每灯的独立 LightDepth 相机/捕获框架。独立局部光源捕获是下一阶段的明确工作。

## 4. 建一个小而有针对性的验证场景

场景包括已有太阳、带窗格的房间、一个 Box 大气区域，以及：

1. 实体窗框和 alpha cutout 多孔板，验证孔洞保持与内部光束。
2. 画面外遮挡物、区域外屋檐，验证其阴影仍能进入区域。
3. 大气盒子的边缘、相机在盒内/盒外、前景遮挡物，验证范围和深度终止。
4. 移动太阳、移动区域、启用世界噪声，验证光向与介质状态各自正确。
5. 空区域、缺失天空、关闭 VolumeLight，验证底层默认输入与资源生命周期。
6. 打开 Screen Space Shadows，以及太阳 cascade/shadow distance 边界，验证采样语义。

在隔离验证工程中验证新增 pass 与既有环境输入。围绕数据契约增加有意义的环境/介质独立性检查，并运行已有 HoAtmosphere 环境验证；不为简单 Inspector 参数绑定制造大量镜像测试。

第一阶段完成标准：一片大气区域里，太阳通过多个窗口形成光束；改密度/柔边/噪声立即可见；无需窗边新灯；区域外投影者仍有效；环境输入回归通过；关闭效果无效果专有资源残留。

## 5. 后续顺序

| 阶段 | 交付 |
| --- | --- |
| v0.1 | 上述共享 Region + HoAtmosphere Medium 发布 + 太阳 HD 闭环 |
| v0.2 | 局部 SD/HD、可选 Light 挂件/绑定、独立局部 LightDepth、墙面自动裁切与多孔遮挡 |
| v0.3 | 明确的多区域规则、多灯共同采样同一介质、共享可见灰尘的一次模拟/绘制 |
| v0.4 | AC 晚阶段效果输入、软效果遮罩、按需 RGB/AOV 与灯组贡献；不使用实心代理轮廓代替效果 |

SD 与 HD 最终都提供，先把最常用天光流程作为共享架构的第一个消费者。完整 SDF 资产工具、粒子系统、导出链不挤进 v0.1。
