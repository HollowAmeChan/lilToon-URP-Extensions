# 重构完成计划

> 本文记录 2026-05-26 重新梳理后的完成口径。前面的文档保留执行记录和设计原则；本文件只回答“现在还差什么才算这轮边界重构完成”。

## 0. 当前完成基线

代码主路径已经完成以下大块切换：

- `ImageProcess` 已从旧 ShoostStack 收敛为最终图像链：Runtime / Editor 主路径改名完成，用户 layer 顺序即执行顺序，旧 AOV composite / semantic mask / `NeedsAovInput` 路径已删除。
- `ScreenProcess` 已承接语义屏幕处理：旧 HoPost 主路径改名完成，规则遮罩改为 `ScreenProcessRuleMask`，运行时读取 `_HoMetadataBuffer*` / `_HoGeometryBuffer*`。
- `MetadataBuffer` 与 `GeometryBuffer` 已拆成独立 RendererFeature：旧 AOV 代码目录删除，旧 `_lilHoAov*` 纹理 alias 与 `HoAOV` / `HoAOVSSS` LightMode 从运行时与材质模板切出。
- `ShadowCast` 已作为 Lighting/Shadow 组分独立：旧 controller / manual list 入口删除，RendererFeature 从 URP visible lights 自动收集，并区分 GameObject layer 与 Rendering Layer。
- 重 debug shader 已进入按需加载主线：MetadataBuffer、GeometryBuffer、ShadowCast、SSS debug shader 都是 feature-local 路径，并由显式生成器收集。

这意味着后续不再以“旧 AOV / HoPost / Shoost 兼容”为主线。剩余工作应围绕消费边界、debug 编排和非 RenderGraph 路径收口推进。

## 1. 完成定义

这轮重构可以视为完成，需要同时满足：

- Runtime / Editor 主路径没有旧 `HoAOV`、`HoPost`、`ShoostStack` 概念入口；旧名只出现在历史文档、参考资料或明确的迁移记录里。
- 用户侧只通过 `ShadowCast`、`MetadataBuffer`、`GeometryBuffer`、`SSS`、`OIT`、`CharacterSpecialization`、`ScreenProcess`、`ImageProcess` 这些 RendererFeature / Volume 入口理解系统。
- `ImageProcess` 不读 MaterialBuffer / GeometryBuffer / ShadowCast / SSS / OIT / CharacterSpecialization 等语义资源。
- `ScreenProcess`、`SSS`、`CharacterSpecialization` 只读取自己真实需要的 MetadataBuffer / GeometryBuffer 项，缺少依赖时有可观察降级，而不是静默读空。
- MetadataBuffer 设置和 debug 不再把 depth / normal / velocity 伪装成自己的输出项；几何项由 GeometryBuffer 负责。
- Debug shader 的加载、收集和缺失降级都可被用户明确控制；公共 debug / tile view 只编排 feature-local view，不拥有资源。
- compatibility path 不再反向约束 RenderGraph 主线；如保留，只作为旧渲染路径 fallback，并有明确释放和 reset 行为。
- `Documentation~/RPComponentRework/` 是当前架构真相；旧 `Documentation~/PostProcessing/` 等历史文档要么标为历史资料，要么按新命名重写。

## 2. 收尾优先级

### P0：消除当前语义不一致

先处理会误导后续实现的边界不一致：

- 2026-05-26 梳理时发现 `MetadataBuffer` 仍有 `LinearDepth`、`WorldNormal`、`Velocity` 相关 channel/debug 枚举残留；这些名称与“MetadataBuffer metadata-only，normal/depth 只由 GeometryBuffer 输出”的完成态冲突。
- 复查 `ScreenProcess`、`SSS`、`CharacterSpecialization` 的 RenderGraph 消费：每条路径列出实际读取的 MetadataBuffer / GeometryBuffer 纹理，并把缺失降级写入运行时诊断或 Inspector 状态。
- 给 `Documentation~/PostProcessing/` 下的旧 HoAOV / HoPost 文档加历史标记，避免它们继续作为当前使用说明被引用。

2026-05-26 已完成第一项：MetadataBuffer channel/debug 中的 depth / normal / velocity 已删除，几何 debug 统一回到 GeometryBuffer。

### P1：debug 完整闭环

当前已有显式 debug shader collection 生成器，但还不是完整 debug 体系：

- 为 MetadataBuffer、GeometryBuffer、ShadowCast、SSS、ScreenProcess、ImageProcess 补 feature-local debug view info，包含 view id、短名、shader 名、是否重 shader、缺失时的降级说明。
- 明确公共 Debug UI / tile view 的最小实现：只读取各 feature 的 view info，不搬运 shader、material 或资源 ownership。
- ScreenProcess rule mask debug 需要单独收口，避免常规效果 shader 继续承担过重 debug 责任。

### P1：RenderGraph 主线收口

RenderGraph 已是主线，但 compatibility path 仍存在于 ImageProcess、ShadowCast 等模块：

- ImageProcess：确认 compatibility path 的 RTHandle 只服务旧路径，不能再影响 RDG effect 资源声明；长期目标是冻结或删除旧路径。
- ShadowCast：保留 receiver ABI，继续让 atlas / light data 由 RDG 发布；compatibility path 只作为 fallback，不再决定 pass/collector/publisher 结构。
- MetadataBuffer / GeometryBuffer：确保 fallback material 与 RTHandle 路径释放、reset、global texture 状态和 RenderGraph 路径一致。

### P2：未来能力准入

这些不是当前完成阻塞项，只有出现真实消费者时才推进：

- `GeometryBuffer.Motion / Velocity`：先保持候选，不默认输出；等 temporal、体积重投影或运动类 ScreenProcess 明确消费后再加入。
- `MaterialBuffer.RoughnessLike / SmoothnessLike / EmissionHint`：按未来 wetness、deferred scene、atmospheric highlight 等真实需求进入。
- `ShadowCast` 的 ScreenProcess receiver：只作为明确 ScreenProcess effect 实现，不让 ShadowCast 反向变成对象分类系统。
