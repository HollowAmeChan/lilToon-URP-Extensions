# 命名迁移表

> 这份表解决旧仓库继续推进时的命名歧义。旧代码路径可以暂时保留旧名，但新语义名必须统一。

---

## 0. 硬规则

新增文档、新抽象、新局部 descriptor、新 review 清单使用新名：

```text
ScreenProcess
ImageProcess
MaterialBuffer
GeometryBuffer
```

旧名只在以下场景出现：

- 引用现有代码路径。
- 描述 legacy behavior。
- 写迁移对照。
- 避免一次性大重命名破坏 git diff。

---

## 1. Post 命名

| 旧名 | 新语义名 | 说明 |
| --- | --- | --- |
| `HoPost` | `ScreenProcess` | 语义感知屏幕处理 |
| `HoPostProcessing` | `ScreenProcess` | 目录迁移期可保留旧路径 |
| `HoPostProcessRendererFeature` | `ScreenProcessRendererFeature` | 新类名方向 |
| `HoPostProcessLayer` | `ScreenProcessLayer` | 新 layer 概念 |
| `HoPostAovMask` | `ScreenProcessRuleMask` | AOV mask 规则迁到 screen process 语义 |

`ScreenProcess` 读取 `MaterialBuffer` / `GeometryBuffer`，服务对象、材质、角色、区域定向处理。

---

## 2. Shoost 命名

| 旧名 | 新语义名 | 说明 |
| --- | --- | --- |
| `Shoost` | `ImageProcess` | 最终图像处理，不再作为概念名扩张 |
| `ShoostStack` | `ImageProcessStack` | 旧 stack 收敛为 image process chain |
| `ShoostPostProcessing` | `ImageProcess` | 目录迁移期可保留旧路径 |
| `ShoostPostProcessRendererFeature` | `ImageProcessRendererFeature` | 新类名方向 |
| `ShoostPostProcessPass` | `ImageProcessPass` | RDG pass owner |
| `ShoostPostProcessLayer` | `ImageProcessLayer` | 图像层 |
| `ShoostPostProcessEffect` | `ImageProcessEffect` | 图像效果 |
| `ShoostPostProcessEffectDescriptor` | `ImageProcessEffectDescriptor` | 局部 effect metadata |
| `ShoostAovComposite` | 迁出到 `ScreenProcess` | ImageProcess 不再拥有 mask / AOV composite |

`ImageProcess` 默认只处理图像链：

```text
ImageChain.Read -> pass -> ImageChain.Write -> swap
```

如果一个旧 Shoost effect 强依赖对象、材质、depth、normal、part bit 或 profile，它应迁入 `ScreenProcess`，而不是继续留在 `ImageProcess`。
如果一个旧 Shoost effect 需要 AOV mask、semantic mask、MaterialBuffer、GeometryBuffer、ShadowCast 或其它额外管线输入，也应迁入 `ScreenProcess`。`ImageProcess` 不提供 semantic image pass 例外。

---

## 3. Buffer 命名

| 旧口径 | 新语义名 | 说明 |
| --- | --- | --- |
| `HoAOV Mask/ID/Surface/Custom` | `MaterialBuffer` | 表面、材质、对象、mask、metadata |
| `HoAOV NormalDepth` | `GeometryBuffer` | depth / normal / motion 等几何输入 |
| `HoAovRendererFeature` | `HoMetadataBufferRendererFeature` | 旧 HoAOV 用户入口已迁到 MetadataBuffer；normal/depth 输出由 GeometryBuffer feature 独立承担 |
| `HoAOV NormalDepth 输出 pass` | `HoGeometryBufferRendererFeature` | 已有独立 RendererFeature 与 fallback 输出 pass |
| `SssSource.rgb` | `MaterialBuffer.SurfaceColor` 或 `DiffuseColor` | 通用表面颜色，不是 SSS 私有 source |
| `SssSource.a` | 待定 | 只有表达通用材质语义时进入 MaterialBuffer |
| `SurfaceData.a` / `Utility` | `MaterialBuffer.TransmittanceHint` | 当前由 SSS transmission radius 消费，不再作为无命名系统预留 |
| `HoAovChannelMask` / `HoAovCustomChannels` / `HoAovObjectChannels` | `HoMetadataBufferChannelMask` / `HoMetadataBufferCustomChannels` / `HoMetadataBufferObjectChannels` | MetadataBuffer 的通道与自定义位类型已迁出旧 AOV 类型层 |
| `HoAovAttachmentLayout` | `HoMetadataBufferAttachmentLayout` | MetadataBuffer MRT attachment 索引归 MetadataBuffer 局部所有 |
| `ViewNormal` | 不作为 Buffer 输出/调试项 | 由 `GeometryBuffer.Normal` + view matrix 派生，必要时由具体 feature 局部计算 |
| `TangentNormal` | 已移出默认输出 | 真实消费者出现后再进 GeometryBuffer |
| `OverallMask` | 不默认输出 | 消费者应读具体语义 |
| `ReservedCustom` | 不默认输出 | 没有命名和消费者不进公共 Buffer |

## 4. Shadow 命名

| 旧名 | 新语义名 | 说明 |
| --- | --- | --- |
| `HoShadowCast` | `ShadowCast` | 独立 Lighting/Shadow 组分 |
| `HoShadowCastController` | 删除 | 旧场景控制器路径已清理，普通入口只保留 RendererFeature 自动收集 |
| `HoShadowCastRendererFeature` | `ShadowCastRendererFeature` | atlas pass owner |
| `HoShadowCastSampling` | `ShadowCastReceiverSampling` | 材质 receiver ABI |
| `HoShadowCastDebug` | `ShadowCastDebug` | feature 局部 debug |

`ShadowCast` 不属于 `MaterialBuffer`、`GeometryBuffer`、`ScreenProcess` 或 `ImageProcess`。它可以被材质 forward receiver 或未来 `ScreenProcess` receiver 消费。
普通使用入口应是 Renderer Data 里的 `ShadowCastRendererFeature`，由 Feature 自动收集当前 camera 的可见灯光。

---

## 5. 迁移顺序

1. 文档和新代码先统一新语义名。
2. 旧类名短期保留，避免一次性大改。
3. 新增局部 descriptor 使用新名。
4. 新增 debug view 使用新短名。
5. 当某个模块完成 RDG 和资源瘦身后，再考虑文件夹/类名重命名。

---

## 6. Review 规则

新增内容如果出现 `HoPost`、`Shoost`、`ShoostStack`，必须说明它是在引用旧代码还是新增概念。

如果是新增概念，应改成：

- `ScreenProcess`
- `ImageProcess`
