# 命名迁移表

> 这份表解决旧仓库继续推进时的命名歧义。旧代码路径可以暂时保留旧名，但新语义名必须统一。

---

## 0. 硬规则

新增文档、新抽象、新局部 descriptor、新 review 清单使用新名：

```text
ScreenProcess
ImageProcess
MaterialBuffer
GeometryBuffer
```

旧名只在以下场景出现：

- 引用现有代码路径。
- 描述 legacy behavior。
- 写迁移对照。
- 避免一次性大重命名破坏 git diff。

---

## 1. Post 命名

| 旧名 | 新语义名 | 说明 |
| --- | --- | --- |
| `HoPost` | `ScreenProcess` | 语义感知屏幕处理 |
| `HoPostProcessing` | `ScreenProcess` | 运行时代码目录已迁为 `Runtime/ScreenProcess` |
| `HoPostProcessRendererFeature` | `ScreenProcessRendererFeature` | RendererFeature 类名已迁移 |
| `HoPostProcessLayer` | `ScreenProcessLayer` | layer 类名已迁移 |
| `HoPostAovMask` | `ScreenProcessRuleMask` | AOV mask 规则迁到 screen process 语义 |

`ScreenProcess` 读取 `MaterialBuffer` / `GeometryBuffer`，服务对象、材质、角色、区域定向处理。

2026-05-25 已完成 ScreenProcess 文件/类名迁移：`Runtime/HoPostProcessing` 迁为 `Runtime/ScreenProcess`，`HoPostProcess*` 运行时类型迁为 `ScreenProcess*`，`HoPostAovMask` 相关类型迁为 `ScreenProcessRuleMask*`，ScreenProcess shader 名迁到 `Hidden/lilToon/URP/ScreenProcess/...`。当前运行时已改读 `_HoMetadataBuffer*` / `_HoGeometryBuffer*`，不再读取旧 AOV 纹理 ABI。

## 2. ImageProcess 命名

| 旧名 | 新语义名 | 说明 |
| --- | --- | --- |
| `Shoost` | `ImageProcess` | 最终图像处理，不再作为概念名扩张 |
| `ShoostStack` | `ImageProcessStack` | 旧 stack 收敛为 image process chain |
| `ShoostPostProcessing` | `ImageProcess` | 运行时代码目录已迁为 `Runtime/ImageProcess` |
| `ShoostPostProcessRendererFeature` | `ImageProcessRendererFeature` | RendererFeature 类名已迁移 |
| `ShoostPostProcessPass` | `ImageProcessPass` | RDG pass owner 已迁移 |
| `ShoostPostProcessLayer` | `ImageProcessLayer` | 图像层类名已迁移 |
| `ShoostPostProcessEffect` | `ImageProcessEffect` | 图像效果 enum 已迁移 |
| `ShoostPostProcessEffectDescriptor` | `ImageProcessEffectDescriptor` | 局部 effect metadata 已迁移 |
| `ShoostPostProcessAovComposite` | 迁出到 `ScreenProcess` 或删除 | ImageProcess 不再拥有 mask / AOV composite |

`ImageProcess` 默认只处理图像链：

```text
ImageChain.Read -> pass -> ImageChain.Write -> swap
```

2026-05-25 已完成 ImageProcess 文件/类名迁移：`Runtime/ShoostPostProcessing` 迁为 `Runtime/ImageProcess`，`Editor/PostProcessing/ShoostStack` 迁为 `Editor/PostProcessing/ImageProcess`，`ShoostPostProcess*` 运行时与 Editor 类型迁为 `ImageProcess*`，shader Hidden 名迁到 `Hidden/lilToon/URP/ImageProcess/...`，编辑器图标目录迁到 `Editor/ImageProcessIcons`。旧 Shoost 名称仅保留在迁移记录和历史说明中。

如果一个旧 Shoost effect 强依赖对象、材质、depth、normal、part bit 或 profile，它应迁入 `ScreenProcess`，而不是继续留在 `ImageProcess`。
如果一个旧 Shoost effect 需要 AOV mask、semantic mask、MaterialBuffer、GeometryBuffer、ShadowCast 或其它额外管线输入，也应迁入 `ScreenProcess`。`ImageProcess` 不提供 semantic image pass 例外。

## 3. Buffer 命名

| 旧口径 | 新语义名 | 说明 |
| --- | --- | --- |
| `HoAOV Mask/ID/Surface/Custom` / `_lilHoAov*` | `MetadataBuffer` / `_HoMetadataBuffer*` | 表面、材质、对象、mask、metadata；旧纹理 ABI 已从运行时移除 |
| `HoAOV NormalDepth` / `_lilHoAovNormalDepthTexture` | `GeometryBuffer` / `_HoGeometryBufferNormalDepthTexture` | depth / normal 等几何输入；旧 alias 已移除 |
| `HoAOV` LightMode | `HoMetadataBuffer` LightMode | 材质 metadata pass 已在 `lilToon` 模板重新对接 |
| `HoAOVSSS` LightMode | `HoMetadataBufferSurfaceColor` LightMode | 表面颜色 pass 已在 `lilToon` 模板重新对接 |
| `HoAOV` NormalDepth 输出 | `HoGeometryBuffer` LightMode | 材质模板新增独立几何 pass，normal/depth 不再混入 MetadataBuffer |
| `HoAovRendererFeature` | `HoMetadataBufferRendererFeature` | 旧 HoAOV 用户入口已迁到 MetadataBuffer；normal/depth 输出由 GeometryBuffer feature 独立承担 |
| `HoAOV NormalDepth 输出 pass` | `HoGeometryBufferRendererFeature` | 已有独立 RendererFeature 与 fallback 输出 pass |
| `HoAovSubject` | `HoMetadataBufferSubject` | 高级对象/材质 metadata MPB 覆盖组件，已迁入 MetadataBuffer |
| `HoAovGroup` | `HoMetadataBufferGroup` | 对象/角色/部件 metadata 分组组件，已迁入 MetadataBuffer |
| `HoAovShaderConstants` | `HoMetadataBufferShaderConstants` | MetadataBuffer shader ABI 常量已改为新命名，旧 AOV 常量类已删除 |
| `HoAovRenderScale` | `HoCharacterRenderScale` | CharacterSpecialization 局部捕获分辨率 enum，不再放在 AOV |
| `SssSource.rgb` | `MaterialBuffer.SurfaceColor` 或 `DiffuseColor` | 通用表面颜色，不是 SSS 私有 source |
| `SssSource.a` | 待定 | 只有表达通用材质语义时进入 MaterialBuffer |
| `SurfaceData.a` / `Utility` | `MaterialBuffer.TransmittanceHint` | 当前由 SSS transmission radius 消费，不再作为无命名系统预留 |
| `HoAovChannelMask` / `HoAovCustomChannels` / `HoAovObjectChannels` | `HoMetadataBufferChannelMask` / `HoMetadataBufferCustomChannels` / `HoMetadataBufferObjectChannels` | MetadataBuffer 的通道与自定义位类型已迁出旧 AOV 类型层 |
| `HoAovAttachmentLayout` | `HoMetadataBufferAttachmentLayout` | MetadataBuffer MRT attachment 索引归 MetadataBuffer 局部所有 |
| `ViewNormal` | 不作为 Buffer 输出/调试项 | 由 `GeometryBuffer.Normal` + view matrix 派生，必要时由具体 feature 局部计算 |
| `TangentNormal` | 已移出默认输出 | 真实消费者出现后再进 GeometryBuffer |
| `OverallMask` | 不默认输出 | 消费者应读具体语义 |
| `ReservedCustom` | 不默认输出 | 没有命名和消费者不进公共 Buffer |

## 4. Shadow 命名

| 旧名 | 新语义名 | 说明 |
| --- | --- | --- |
| `HoShadowCast` | `ShadowCast` | 独立 Lighting/Shadow 组分 |
| `HoShadowCastController` | 删除 | 旧场景控制器路径已清理，普通入口只保留 RendererFeature 自动收集 |
| `HoShadowCastRendererFeature` | `ShadowCastRendererFeature` | atlas pass owner |
| `HoShadowCastSampling` | `ShadowCastReceiverSampling` | 材质 receiver ABI |
| `HoShadowCastDebug` | `ShadowCastDebug` | feature 局部 debug |

`ShadowCast` 不属于 `MaterialBuffer`、`GeometryBuffer`、`ScreenProcess` 或 `ImageProcess`。它可以被材质 forward receiver 或未来 `ScreenProcess` receiver 消费。
普通使用入口应是 Renderer Data 里的 `ShadowCastRendererFeature`，由 Feature 自动收集当前 camera 的可见灯光。

---

## 5. 迁移顺序

1. 文档和新代码先统一新语义名。
2. 旧类名短期保留，避免一次性大改。
3. 新增局部 descriptor 使用新名。
4. 新增 debug view 使用新短名。
5. 当某个模块完成 RDG 和资源瘦身后，再考虑文件夹/类名重命名。

---

## 6. RendererFeature 显示名

Renderer Data 里的 RendererFeature 防重名显示统一使用 `Ho-<规范模块名>`，模块名本身不带空格，不再混用 `lilToon-`、`HoSSS` 或 `HoCharacter`。

| 模块 | Renderer Data 显示名 |
| --- | --- |
| ShadowCast | `Ho-ShadowCast` |
| MetadataBuffer | `Ho-MetadataBuffer` |
| GeometryBuffer | `Ho-GeometryBuffer` |
| SSS | `Ho-SubsurfaceScattering` |
| OIT | `Ho-WeightedOIT` |
| CharacterSpecialization | `Ho-CharacterSpecialization` |
| ScreenProcess | `Ho-ScreenProcess` |
| ImageProcess | `Ho-ImageProcess` |

同一轮已同步 Frame Debugger / RenderGraph pass 名、Volume 菜单/displayName 和相关缺 shader 日志。shader Hidden 名、包名、命名空间和材质 ABI 不属于这条显示名规则。

---

## 7. Review 规则

新增内容如果出现 `HoPost`、`Shoost`、`ShoostStack`，必须说明它是在引用旧代码还是新增概念。

如果是新增概念，应改成：

- `ScreenProcess`
- `ImageProcess`
