# 架构边界：语义掩码（从 bit 到覆盖率）

> **状态：现行架构边界说明**（结论 2026-09-14 定稿，2026 文档审核时按当前代码校正）。
> 现象、实测数据与修复落点见 `CHANGELOG.md` 0.2.0「掩码抗锯齿」。
>
> **v2（角色特化 R2）**：语义输入换成 **OB 身份池 + 部件标签 + 覆盖率**，那条"把二值位整体过盒核伪造抗锯齿"的
> feature 级服务与它的 5 个开关**已删除**。
> **v3（R6/R7）**：MetadataBuffer（bit 掩码的载体）整块删除，bit 掩码彻底退出管线。
> 下文第 2 节起记录的机制与坑仍然成立 —— 它们是"为什么不再用 bit 表达覆盖"的依据，只是当时的实现已经不在。

## 结论

语义位的契约曾是 **RGBA(bits)**：八个语义（CharacterFull / Face / FrontHair / Eye / EyeRevealArea / Accessory /
CharacterBody / Reserved7）各占 1 bit，写在 RSUV（renderer shader user value）的低字节里。
**1 bit + 单采样 = 没有亚像素覆盖可言**，所以：

- 语义位适合当**身份 / 选择**用（这个像素属于谁、要不要参与某个效果）；
- 一旦把它当**轮廓 / 覆盖**用（投射、染色、羽化、描边），消费端拿到的必然是硬边，**必须由消费端自己补回低频**；
- 这份低频**必须由我们自己产出**，不能指望外面的 AA（见坑 6）。

本管线现在的答案不是"把 bit 模糊一下"，而是**换掉承载方式**：身份改为逐样本 16 bit ID（OB 身份池），
覆盖率由 OB resolve 直接产出连续场，语义由表解压（AC 的 Selection 池）。见下文「现在管线里怎么做的」。

## 为什么 bit 存储有这个弊端（机制）

> 这一节写的是**旧实现（MetadataBuffer）**的机制。它已被 R6/R7 删除，但机制本身是这条边界结论的依据，
> 所以保留；括号里给出今天对应的实现。

1. **RSUV 是 per-renderer 的。** 旧路径 `HoMetadataBufferGroup.WriteRendererValue` →
   `PackRendererUserValue(objectCustomMask, characterId, partId, flags)` → `SetShaderUserValue`：一个 `uint`，
   低字节 `& 255u` 就是 8 个语义位。它表达"这个 renderer 属于哪些语义"，**本质装不下 per-pixel 覆盖**。
   （今天同样的 RSUV 由 `HoObjectBufferGroup` 写：低 16 bit = `(组, 槽位)` **身份**，不再承载 bit 语义；标签在部件行表里。）
2. **写入端把它压成 0/1。** 旧 pass 用 `subjectValid = step(0.0001, subjectCoverage)` 把
   `objectCustom0 = DecodeObjectCustom0(...) * subjectValid` 二值化 —— 上游就算有部分覆盖，也会在这一步被丢掉。
3. **单采样是硬约束。** 掩码所在的那些 RT 全部 `msaaSamples = 1`、`bindMS = false`（理由见 `MSAA.md`：
   它们会被材质与后处理当普通纹理采样、也可能跨帧重投影）。于是相机 MSAA 提供的覆盖信息**永远进不来**。
   （今天这条约束仍然适用于所有"会被采样 / 重投影"的 RT；OB 的身份池是**自建 MSAA**，属于刻意的例外。）
4. **线性滤波只能改台阶幅度，改不了边的位置。** 单采样二值场里每个 texel 的翻转点是固定的，任何核（双线性、
   更多抽头、多趟串联）都只能把台阶做小做匀；边的**亚像素相位在写入时就没进缓冲**。推论：
   - 宽度 W 的核最多给出 ≈ W 级台阶，单级台阶下限 ≈ `1/W`；
   - **两级线性滤波在数学上等于一个等效核**，峰值台阶由较宽的那一级决定 —— "多模糊两遍"不会叠加收益。
     两级真正的价值是**分工**（闸门 1px / 半影艺术半径）与复用。

## 我们踩过的坑

### 1. 抽头落在整 texel + 点采样 → "柔化无效"的错觉

旧的 9 抽核（中心 0.24、环 0.095）抽头都在 ±softness 的**整数 texel** 上，又用点采样读，于是跨竖直边的响应只有四个值：`0 / 0.285 / 0.715 / 1` —— **两级 2px 平台夹 0.43 台阶**；把「柔化像素」从 2 调到 6 只是把平台拉宽，**单级台阶还是 0.43**。体感就是"柔化这个参数没用"，相机一动边缘还整 texel 跳档。

修法与实测（跨竖直边的逐 texel 台阶剖面）：

| 核 | 剖面 | 单级最大台阶 |
| --- | --- | --- |
| 旧 9 抽整数偏移 + 点采样 | `0.285 0.000 0.430 0.000 0.285 0.000` | 0.430（含 2 个平台列） |
| 黄金角螺旋 + 双线性 | `0.033 0.243 0.441 0.248 0.035` | 0.441 |
| **扁平盒 + 双线性（采用）** | `0.200 0.200 0.200 0.200 0.200` | **0.200 = 1/宽度（理论下限）** |

结论：**抽头必须落在 texel 之间（双线性），核用扁平盒而不是高斯** —— 同宽度下高斯把权重堆在坡道中段，台阶比盒高约 2.2 倍。宽度下限 1px（0.5px 半径在单像素内仍跳 0.84，没有收益）。

### 2. 只软化一项、其余是二值门 → "下半段模糊、上半段被二值化裁"

`shadowMask = shiftedHair × receiver × same` 里只有 `shiftedHair` 是软的；`receiver`（Face 位）是**点采样二值**，于是投影的上边界（发际线）被硬裁一条，下边界（半影）反而平滑。

结论：**裁剪边与半影是两件事**。裁剪边只需要**亚像素**（1px 量级），不能套艺术柔化半径 —— 套上去投影会在贴到投影源之前就淡掉，把接触区掏空。

### 3. 拿未模糊的 bit 和软场做算术

「避开前发」原来是 `shiftedHair − originalHair × keepOffHair`，其中 `originalHair` 是**未柔化的二值 bit**：那条切边由 bit 自己定位，任何柔化值都移不动它，表现就是"边缘一圈叠不上去"。而且它本来就冗余 —— `receiver`（Face 标记）已经把投影限制在脸上。**该参数已删除。**

结论：不要让"未模糊的 bit"和"软场"做算术；两者要么同源（读同一张副本），要么各自管各自的边界。

### 4. 语义通道**故意**丢了 alpha（这是设计，不是 bug）

旧实现里：`lilHoMetadataBufferResolveSubjectCoverage` 在 `LIL_RENDER == 2`（透明队列）时直接返回 `maskWeight`，
注释写着"透明材质仍占满网格面积"；而掩码 pass 是 `Blend Off + ZWrite On + ZTest LEqual`。
于是**半透明前发 alpha≈0 的区域照样写 `FrontHair = 1` 并抢走深度** —— 它的投影是"整块网格"，不是可见的软边形状。

结论：语义通道表达**归属**，不表达**覆盖率**。消费端要"可见形状"就得另取覆盖率（几何覆盖率 / 材质 alpha / SB 的 owner 对齐），不要指望语义位。**这条结论与具体实现无关，今天仍然成立。**

### 5. 把"通道预算"当成了瓶颈

第一反应容易是"8 个语义挤在一个通道里所以没法抗锯齿，得腾通道"。事实相反：语义位所在的 RT 是 **R16G16B16A16_SFloat**（每张 4×16bit，两张共 128 bit）却只装了 8 个布尔 —— **容量早就够，是"bit 编码"把信息摁掉了**。

但关键推论是：**改编码本身不产生覆盖**。opaque 材质写入时 alpha = 1，改存 value 也还是 1.0。覆盖只有三个来源：①几何被多次采样（MSAA / 超采样 + 逐语义 resolve）；②材质上的 per-pixel 遮罩（纹理，天然软边）；③材质 alpha（透明队列 —— 语义位当前故意不用，见坑 4）。**OB 身份池走的是第 ① 条**（自建 MSAA + 逐样本身份 + resolve 出覆盖率）。

### 6. 以为"外面的 AA 会兜底"

- **相机 MSAA 进不来**：语义掩码是屏幕空间 pass 的产物，而这类 RT 被强制单采样（`MSAA.md`）。
- **FXAA 会漏**：它按对比度判据找"1px 硬边"，对这种跨 4~5px、单级 0.43 的多级台阶会被判成"不够像边"而跳过。
- **TAA 不是错，但要看时机**：它靠 jitter 让二值掩码每帧落在不同 texel 上再跨帧累积，理论上能补相位；但如果合成排在 TAA 之后（`passEvent` 设晚），它看不到这条边。

结论：这类信号**自己产出**，并且要按"AA 全关 / MSAA 开 / 后处理 AA 开"各跑一遍。

### 7. 混合模式的对比度差异会伪装成几何问题

同一条 mask：正片叠底的边缘步进 = `color × (1 − shadowColor)`（只取决于投影色，永远是一层乘暗）；线性混合 = `|color − shadowColor|`（投影色接近脸色时可以任意小）。于是"换成线性混合就没事了"—— **那是把对比度压到看不见，不是修好了**。

结论：判定假象要看**掩码本身**（当前 debug 4「前发投影遮罩」）而不是最终画面；遇到"换个参数就没事"时，先分清是几何变了还是对比度变了。

## 现在管线里怎么做的（OB → AC → 消费者）

- **覆盖率的来源**：**OB 身份池**（逐样本 16 bit ID → MSAA resolve 出最多 4 层 `(组, 槽位)` + 每层线性覆盖率）加**部件行表的标签位掩码**。
- **谁解压**：**AC（`Ho-AttributeComposite`）**。`HoACSelectionResolve.shader` 一趟全屏 pass 读 OB 身份池，按 `HoSemanticSchema` 把每条 lane 的覆盖率算成 `Σ cov_i · 该层带不带这一位`，写 4 张 RGBA8（每张两条 `(SemanticId, coverage)`）= **AC Selection 池**。产物本身就是连续场，不做任何滤波。
- **消费者只经 `HoAC_*` 查询**（`Runtime/AttributeComposite/Shaders/HoACQuery.hlsl`）：`HoAC_Selection`（按 lane 取覆盖率并校验图内 SemanticId）、`HoAC_Predicate`（物体位谓词）、`HoAC_Identity / Group / Layer0Group / TotalCoverage`。**不许自己解码 OB/SB 的 packing**，但 RenderGraph 的物理读依赖仍要各自声明。
- **角色特化**是第一个消费者：它把 AC 的池转置成自己的两张位平面（`HoCharacterObjectSemantic.shader`，图记在它自己名下，见 `Ho-AttributeComposite.md` §9.2），下游（前发投影的半影滤波、眼透的羽化）仍在位平面上做逐 texel 抽样；同角色判定改用 `HoAC_Layer0Group`。
- **用户级开关为零**：没有「抗锯齿宽度」，也没有每个效果的「读取抗锯齿掩码」——位平面恒为连续场，硬边只可能来自用户把柔化调到 0。
- 通道契约：`objectSemantic.low/high`（见 `Ho-ChannelContract-v1.md`：**当前产出者是角色特化自己的打包 pass，读 OB 身份池 + 覆盖率**）。

## 新特性要遵守的

1. **先想清楚要的是"身份"还是"覆盖"。** 身份用 ID（OB `IdentityId`）；覆盖用 **OB 覆盖率**（身份池逐层覆盖率直接就是它，不要再从 bit 里补）。只有在 OB 不覆盖的地方（例如材质级、屏幕空间自产的软场）才另说。
2. **可以整体滤波的只有"每通道一个语义"的场**：OB 位平面天然满足（已经是覆盖率的加权和）。**绝对不要**对 OB 的 `Id0/Id1`（打包 ID）、SB 的 `Classification`（profile / class byte）与 `Material`（roughness / metallic / thickness）、SSGI 的 metadata（打包深度 / 法线 / ID）、角色特化的 `eyeData`（打包 alpha/depth/id）、以及任何 byte ID 做线性模糊 —— 平均出来是垃圾。
3. **不要覆盖原位图**：ScreenProcess 规则遮罩、AOV 导出、轮廓 source 通道、debug 视图都吃精确值，新增消费端要自己另开一张。
4. **裁剪边与半影是两件事**：裁剪边只要亚像素（1px 量级），半影才用艺术半径；不要把二者混成一个旋钮。
5. **不要依赖外部 AA**；新增这类消费端要按 MSAA 开关 + AA 全关各跑一遍。
6. 需要更宽的过渡时**直接调该效果的柔化旋钮**（读取时的 box 会按 texel 摊开），不要靠串联滤波 —— 串联的峰值台阶由较窄那级决定，不会更平滑。

## 遗留（已由 OB 实现）

线性滤波的天花板就是"把台阶做小做匀"，真正拿回**亚像素相位**的唯一路是让掩码**自带逐 sample 覆盖**。OB 就是这条路的落地：

- 逐样本写 16 bit ID（一个样本只属于一个部件）→ resolve 数票得到"每层身份 + 覆盖率"，覆盖率天然是 `k/N` 级（N = 平台协商的采样数，与相机 AA 解耦）。
- 语义由**表**解压（身份 → 标签），所以覆盖率的相位直接进了语义场，不需要"最近 sample 语义"这种近似。
- 平台不支持多采样时退化成 0/1（`_HoObjectBufferActualSamples` 可见），此时才需要消费端的 1px 亚像素读。
- 相机 MSAA 开时仍有一条白拿的近似：`HoGeometryBufferResolve` 输出的 G（最近表面占有率）可以给"该像素属于哪个语义"的覆盖率加权（见 `MSAA.md`）。
