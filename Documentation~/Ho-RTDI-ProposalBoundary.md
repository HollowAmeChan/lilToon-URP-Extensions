# Ho-RTDI 采样策略相邻边界与分辨率

第42步扩大第41步严格零F0重要性策略的支持验收，修复相邻策略的空间复用失败，并将DI策略与共享GI引用编译隔离。没有增加材质参数、资源、pass或射线，物理Shade与NRD参数保持。

## 独立参考与失败基线

`RunF0Boundary/Compatibility`使用共面的左右半Quad，白色diffuse材质、F0分别0/1⁄255、相同roughness；左右布局交换，64/128两种分辨率，none/temporalSpatial两种复用，共8配置。每配置192预热/512观察，以60Hz固定NRD验证时钟，观测同一中心世界区域。分别评分左右半区和各侧邻缝两像素条带，共32项；CPU按当前相机及分辨率独立计算平面交点/Lambert/点灯衰减。

原raw3%、filtered5%、frameL1<.35保留；增加缺失绿色通道的raw真值检查与filtered green<总参考2%检查。所有区域确实调度RELAX，时间复用状态有断言；不按输出调光或构造参考。

基线两条30/32通过，64、左F0=0/右F0=1、复用开启失败：

## 改动与适用范围

共用`HoDIUsesRgbImportance`判定目标回调与材质相容性，防止后续规则漂移。现有SDK空间重采样已开启material-similarity hook；在原roughness/F0/diffuse阈值前增加双方属于同一重要性策略的条件。0与非零F0两侧不再跨此边界进行空间reservoir复用，各侧内部仍可复用；采样目标与物理响应未改。

这是本应用为控制方差/过滤稳定性增加的资格限制。SDK数学上允许不同目标，原本所有回调也一致；不把本条件解释为SDK正确性要求。代价是边界附近的可复用邻居减少，并非任意不同材质间都禁止复用。时间F0切换仍通过第41步独立门槛，NRD的邻域过滤未被额外关闭。

核对用户RAB surface/material契约，以及pinned SDK在读取邻居前调用`RAB_AreMaterialsSimilar`的原始源码。编译与采样数据布局不变。

## 共享GI隔离与部署

进一步检查发现GI bridge直接包含DI bridge，借用其secondary-hit的DI initial sampling。第41步虽未编辑GI文件，目标回调变化曾经传入共享GI include；此前“GI未变”表述不完整。本步默认启用DI RGB策略，GI include显式编译关闭，恢复原亮度目标，同时令新增相容性条件在GI中恒为true。没有推进新的GI功能。

必要的GI两条GPU回归通过，覆盖既有五阶段、sky/emissive/secondary解析能量、世界遮挡、temporal/spatial/history及独立输出/debug。两个Win64 Mono release errors0，实际D3D12两条全suite通过，D3D11 inactive通过。立体Cutout连续/阶跃frameL1 RG .179656/.233885、compat .179901/.234284，变化像素.277329/.285264，仍满足原门槛但短期响应仍待改善；非零F0 primary spec起点通过。原Player noise MSE .000526/.000510，数值差异保留。

DI生成器/原始SHA、Roslyn和提交前检查通过，无新增DI/GI shader诊断。不修改用户原古堡或旁边仓库。本步未对GI做Player新增验收，GI证明范围限于既有两条Editor GPU回归；不扩大结论。

下一项应继续验证更多相邻材质、灯分布与更大尺寸，以及GPU预算/动态短期响应。需要更多复用机会时再评估兼容邻居选择，保留无复用和原始采样对照，不扩张最终合成或通用PT。
