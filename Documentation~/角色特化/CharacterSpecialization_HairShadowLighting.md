# 前发投影：主光方向与按需调试

2026-11-24。

## 使用

在 `Ho CharacterSpecialization` 的「前发投影」展开后调整 **主光方向影响度**：

- `0`：沿用已有投影角度，新旧 Profile 默认均不改变既有画面。
- `1`：在有效范围内跟随当前相机的 URP 主方向光。对象需要关联 GD ReferenceFrame，前轴应指向脸的正前方。
- 中间值：混合固定方向与受光方向的偏移向量。相反方向会经过短偏移，不做会翻转的角度插值。

光线先投影到角色面部朝向平面，再用当前视图的 VP 矩阵转换为屏幕像素方向，因此会响应转头、相机绕行、侧视、相机滚转和宽高比。投影距离、透视衰减、颜色、柔化及扩散仍使用原有控制，不根据掠射角无限拉长。

主光来自当前相机的 `mainLightIndex / visibleLights`，不延迟查询全局 Sun。背光、接近切线、正对光源的退化投影会平滑减小自动影响；没有主方向光、有效 GD 身份或朝向时回退固定角度。这仍是屏幕空间艺术化模拟，没有使用真实头发到脸部的间距。

## 调试与资源

RendererFeature 原有调试下拉新增 **前发投影方向**（枚举值 22）。只显示脸/前发语义区域：RG 为最终二维偏移向量映射到 0..1，B 为实际应用的主光影响度。调试选择仍在原有 Feature 设置中，不新增常驻方向 RT。

- `Off` 不创建角色特化的调试输出，也不安排最终调试呈现。
- 方向、GD 参考系视角和相机角度因子只消费参考系缓冲，不再触发眼睛捕获。
- RenderGraph 的眼睛颜色纹理按消费者创建；兼容路径的颜色/眼睛数据 RT 也按需分配，需求关闭后释放。兼容路径的 Face/Eye 绘制使用同一组需求门控。
- 眼透仍需要眼睛捕获；前发漫反射仍需要受光脸捕获。它们属于正常效果输入，不随 Debug Off 关闭。
- 身份池、角色语义遮罩及正常效果的模糊中间结果仍由真实消费者保留，调试关掉不影响正式合成。

## 验证

隔离图形 batch editor 入口：`lilToon.URP.Extensions.Editor.CharacterSpecialization.HoCharacterHairShadowValidation.ValidateGpu`。包含投影有限差分 CPU 参考与生产 HLSL 的 GPU 对照、透视/正交、横竖屏、滚转、头朝向、主光/退化回退；并用正式合成 Shader 验证真实遮罩的左右/上下位移。

同时检查所有调试枚举的捕获需求、兼容 RT 的开关释放，以及 Off/方向/角度/参考系视图实际记录的 RenderGraph pass 与捕获句柄。既有叠加顺序 GPU 回归仍需通过。以上不替代完整角色场景的视觉、XR 或性能验收。

Unity 6000.3.15f1 的 D3D11 与 D3D12 均已通过：每个 API 1010 组方向 GPU 对照、正式合成 Shader 的左右/上下遮罩位移，以及 1440 组原有叠加回归。结果摘要与源文件 SHA256 记录在 `Tests~/CharacterSpecialization/HairShadowLighting-20261124/`。
