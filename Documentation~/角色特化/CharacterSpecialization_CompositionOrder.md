# 角色特化叠加顺序

2026-11-23。`Ho CharacterSpecialization` 右侧效果列表与 ImageProcess / ScreenProcess 一样支持原生手柄拖动排序。列表从上到下合成，眼透默认位于最下方。

默认顺序：**前发投影 → 前发漫反射 → 增强描边 → 主体描边 → 眼透**。除把眼透移到最后外，其余效果保留旧 Shader 的实际合成先后。旧 Inspector 曾把主体/增强描边的行顺序写成相反顺序，现在显示与执行统一。

## 使用与兼容

- 拖动左侧手柄调整顺序；保存 Volume Profile 后顺序保留，可撤销、重做。
- 五种效果各保留一份参数。启用开关和“×”只关闭效果，保留其参数及排序位置；侧栏仍用于启停、查找和恢复参数默认值。
- 恢复某个效果的默认参数不重置整份排序，也不影响其它效果。
- 排序存储在原有 `Effects` 容器中的 `compositionOrder`，不迁移或重命名已有参数、类型和 GUID。
- 未记录顺序的旧 Profile 使用新的默认顺序，即眼透最后。空、重复、不完整或含未知枚举的顺序保留有效唯一项，并按默认顺序补齐；运行时解析不修改 Profile。
- 顺序与其它效果参数仍由同一个 Volume Effects 容器选择，不对枚举序列做数值插值。

## 渲染范围

排序控制最终的颜色叠加。语义、角色捕获、遮罩和模糊等准备阶段保留原来的资源依赖；脸色扩散仍来自受光脸，雾气颜色仍以原图底色为参考。

合成仍使用原有的单个全屏 pass；没有为五个效果增加五次全屏绘制。每相机把顺序解析成两份向量，RenderGraph 记录时按值保存，兼容路径和 RenderGraph 路径均在合成前绑定。原有各效果的混合模式、强度、阈值、调试视图与源 Alpha 保留。

验证入口为 `lilToon.URP.Extensions.Editor.CharacterSpecialization.HoCharacterCompositionValidation.ValidateGpu`，需在隔离的图形批处理编辑器执行。覆盖全部 120 种排列、保存/撤销/重做、旧字段、非法顺序、材质绑定、行高及 GPU 颜色对照；GPU 对照使用生产合成头文件和独立 CPU 参考。它不替代完整角色、透明/XR 画面或性能验收。
