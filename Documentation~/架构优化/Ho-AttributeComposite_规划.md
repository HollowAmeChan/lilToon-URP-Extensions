# Ho-AttributeComposite（AC）规划

运行时属性合成器。输入 **OB + SB**，输出下游真正消费的 ID / 覆盖率 / 属性图。

## 边界

- **输入**：ObjectBuffer（逐物体轴）+ SurfaceBuffer（表面轴）。**GB 不喂 AC**——几何门控由消费端自己读 GB。
- **输出**：叠完的那一份图（下游消费的是它，不是各 buffer 的原始图）。
- **OB 与 SB 各自带自己的 selection**，都进 AC 叠。
- **只吃 AC 的消费者**：ScreenProcess、角色特化（两者都是图层链处理 / 画面调整，帧序靠后且固定）；SSS / PLR 是"数值读 SB、遮罩读 AC"。
- **命名**：不用 Cryptomatte。真正合规的 Cryptomatte 以后单独规划，或由 AC 直出（直出的好处：导出后外部处理与 Unity 内处理吃同一份数据）。

## 递进覆盖（已定）

```text
纯值（底） < object < surface（顶）
```

| 层 | 来源 | 说明 |
| --- | --- | --- |
| 纯值 | 全屏 fallback | **只在代码里表示**，不占通道；"没人写时的缺省" |
| object | OB 的 palette 表 | 逐物体属性（类别 / 标签 / 朝向） |
| surface | SB 的逐像素数值 | 物理真值，优先级最高 |

三条来源 + 一条覆盖链，不是三种纹理。

## 帧序

在 **opaque 之后**（合成的是"最终画面上每像素是谁、表面是什么样"）。偏序：`{OB, SB} → AC → SSS / OIT / PLR / 角色特化 / ScreenProcess`。

## 通道

| 通道 | 内容 |
| --- | --- |
| AC 合成结果 | 具名遮罩 + 覆盖率 + 合成属性（**唯一**的运行时遮罩来源） |

## 待定

1. **纯值的载体**：AC 的常量表（建议）还是各消费端各自的默认值。
2. **按属性合成还是按遮罩合成**：每属性一条覆盖链，还是先合成"谁的属性生效"再取值。
3. **AC 是否直出**：直出即与 Unity 内处理吃同一份数据；不直出则留给将来的 Cryptomatte feature。
4. **消费者是否允许直读 OB/SB 原始通道**：建议禁止，否则会长回"各读各的"。
