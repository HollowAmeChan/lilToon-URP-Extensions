# Ho-AttributeComposite（AC）规划

**所有后期图像链处理的唯一输入口**：它生产下游吃的东西——合成后的遮罩与逐像素属性；下游只吃它。

> **状态：定位、输出形态、查询 API、覆盖链、导出面全部冻结。** 实现归 R4。
> AC **不画几何、不画表面**：它只读 OB + SB，把"三个来源"压成"一个每像素答案"。

---

## 1. 边界（冻结）

| 项 | 内容 |
| --- | --- |
| **输入** | **OB + SB**。**GB 不喂 AC**——几何门控由消费端自己读 GB |
| **输出** | 合成属性图 + 查询 API + manifest（§2） |
| **只吃 AC 的消费者** | ScreenProcess、角色特化（图层链处理 / 画面调整，帧序靠后且固定）；SSS / PLR 是"数值读 SB、遮罩读 AC" |
| **禁止** | 消费者**不许直接读 OB/SB 的原始图**，也不许自己再攒一套语义图；**遮罩只有一个来源 = AC** |
| **不负责** | 不定义"这是谁"（OB 定）、不定义"表面是什么样"（SB 定）、不做合规导出（导出层做，§6） |

**名字**：`HoAttributeCompositeRendererFeature`（代码目录 `Runtime/AttributeComposite/`）、**`HoAttributeCompositeVolume`**（**调试入口**）、契约登记族 `ac.*`。**UI 按 `Ho-UI_风格规范.md`**：调试在 Volume，feature 只放高级设置 + 兜底默认值 + 消费者登记表（只读汇总）。

**覆盖链（冻结）**：`纯值 < object < surface`。纯值是**全屏 fallback**，只在 AC 的常量表里表示、**不占通道**；递进链是**覆盖**，不是求和。

---

## 2. 输出（冻结）

AC **不为每个消费者烤遮罩图**。它发布**一份可查询的合成结果 + 一个查询 API**；要烤成图的效果自己用 API 烤，烤出来的图记在**它自己**名下。

| 输出 | 内容 | 形态 |
| --- | --- | --- |
| **AC 合成属性图** | 已 resolve 的逐像素答案：`materialClass` / `curvature` / `transmittanceHint` / SSS profile / 预留 | AC 的 pass 写，1~2 张 RGBA8（清单封闭，packing 实现时定） |
| **身份池**（引用） | OB 的身份池（ranked：组 / 槽位 / 覆盖率，`K=N=4`）——**SB 不写身份 ⇒ 不复制**，AC 只发布句柄 | 引用 |
| **语义槽**（引用） | OB 的槽与 SB 的槽，按 `object < surface` **取或**（采样时叠）⇒ 不复制 | 引用 |
| **朝向**（引用） | OB 的 `Facing`（逐物体写入时已是逐像素）⇒ 不复制 | 引用 |
| **查询 API** | §3 的 `HoAC_*` | API |
| **manifest** | 名字 → ID → 条目属性（组 / 部件 / 标记 / 物体位）；运行时表 | 常开（小） |

- **只有属性要 resolve**，所以 AC 真正自己写的图只有合成属性图那一两张；其余是句柄 + 采样规则。
- AC 只装"**把三来源压成一个每像素答案**"的东西；**不往里塞新语义**（判据见 §7）。

---

## 3. 查询 API（冻结的接口形状）

| 侧 | 谁做什么 |
| --- | --- |
| **C#** | feature **声明它要哪些名字**（具名 ID / 属性）；构造时经 manifest 解析成 ID；**解析不到 → 报诊断，不静默** |
| **shader** | `HoAC_Mask(id)` / `HoAC_Group(groupId)` / `HoAC_Slot(slot)` / `HoAC_Attribute(attr)` / `HoAC_Coverage()`，在身份池 / 语义槽 / 属性图上 **multi-tap**，按 ID 匹配加权 |
| **登记** | 消费者必须**登记**自己读了哪些条目（debug 可见）；没登记的读不到 |

- **名字只在重建时解析一次**，像素里只有 ID 比较 ⇒ 便宜。
- `HoAC_Mask` 的语义 = `Σ_i cov_i · [条目_i 命中 X]`（**不是取某一层**）；`HoAC_Group` 用组做同样的事；`HoAC_Slot` 直接读固定语义槽（`object < surface` 取或）。
- **AC 的 pass 只有一趟，服务所有消费者**（不是 per-consumer）。

---

## 4. 覆盖链逐属性解释（冻结）

| 属性 | 纯值（底） | object | surface（顶） |
| --- | --- | --- | --- |
| 遮罩 / 覆盖率 | 0（没人写） | 身份池：ID + 覆盖率 + 物体位 | **语义槽的材质覆盖**（按槽覆盖） |
| 分类 / 曲率 / 透射提示 / SSS profile | AC 常量表的全屏缺省 | 条目的属性（palette 行） | SB 的 `Classification` / 材质参数 |
| 朝向 | 无（缺省 = 不生效） | 组表（forward / side） | 材质**不覆盖**朝向 |

身份的"合成"不是覆盖：**身份池按覆盖率加权**（一个像素可以同时属于多个物体）；只有**语义槽**走"取 surface"。

---

## 5. 帧序与生命周期（冻结）

- **opaque 之后**：`{OB, SB} → AC → SSS / OIT / PLR / 角色特化 / ScreenProcess`。
- **GTAO 在 AC 之前 ⇒ 吃不到 AC 的遮罩**：AO 的"谁参与"只能靠 layer mask / 材质意图。
- **每帧重建**：身份池 / 语义槽 / manifest 随声明重建（RSUV 不序列化 ⇒ 每次重建都要重写；声明变更 ⇒ 重建表 + 报诊断）。
- **合成属性图按需分配**：没有消费者声明属性就不分配、不写。
- 平台不支持 StructuredBuffer（shader level < 4.5）⇒ 整条不跑并告警，**不静默降级**。

---

## 6. 导出面（数据面冻结，实现待排）

- **导出的唯一输入 = AC 的合成身份池 + manifest**（**不读 OB / SB 的原始图**）⇒ **导出后外部处理与 Unity 内处理吃同一份数据**。
- 导出是 **L5 的一层、独立 feature**，**不是 AC 的一部分**；**AC 不写 EXR**。
- 编码转换（导出层自己的事，登记在案）：`MurmurHash3_32` → `uint32_to_float32` **位重解释**（含指数位修补）→ **float 通道**存储；manifest **内嵌**（OpenEXR 3.0+ 的 `idmanifest`，sidecar 不被支持）；按 level 拆分（`crypto_object` / `crypto_asset` / `crypto_material`）。
- **现在不做**：EXR 写出、manifest 内嵌、Nuke 验证 —— **R6 之后单独立项**。
- **精度口子**：运行时覆盖率 8 bit；导出若要更高精度，由导出模式决定是否升 16F（口子留着，现在不动）。

---

## 7. 准入与拒绝

- **判据**：这个量是不是"**把多来源压成一个每像素答案**"？是 → AC；不是 → 回它自己的轴。
- **拒绝**：几何 → GB；表面数值 → SB；身份 / 逐物体量 → OB；效果调参意图 → 材质轻量参数；**纯导出的编码与写出 → 导出层**。
- AC 的产物**只有一个来源**（AC 自己）；消费者不许再攒一套。

---

## 8. 执行

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| **R4** | AC 落地：合成属性图 + 查询 API + manifest + 消费者登记 / 诊断 + **调试与登记（V2 §6.1）** | ScreenProcess 的 20 个 source 收成 1 族；角色特化只读 AC |
| **R5** | **消费者输入切换**（V2 §6.2）：ScreenProcess 的 20 个 rule source → AC 具名条目（含**旧序列化配置迁移**与 `Requires*` 诊断家族替换）；角色特化 → AC（组 / 物体位 / 覆盖率）+ SB（表面色）；**两者自己的 debug 视图与登记一起改** | 行为不变或更好；`Requires*` 家族消失；解析不到的名字在视图里报出来 |
| **R4 之后** | 与 OB / SB 一起进 R6：删 MetadataBuffer | 全仓库无 `_HoMetadataBuffer` 引用 |
| **R6 之后** | 导出 feature 立项（读 AC 的身份池 + manifest） | 外部处理与 Unity 内处理吃同一份数据 |

**AC 自己的 debug 视图要能看到**：合成属性图、合成语义槽（`object < surface` 叠完的结果）、**消费者登记表**（谁声明了哪些条目）、以及**解析失败 / 未声明条目**。

---

## 9. 冻结决议

1. **AC = 所有后期图像链处理的唯一输入口**；下游只吃 AC，不读 OB/SB 的原始图，也不再各自攒语义图。
2. **输出形态 = 可查询**：一份合成结果 + 查询 API；**不为每个消费者烤遮罩图**（要烤由消费者自己用 API 烤，图记在它自己名下）。
3. **只有属性要 resolve**：AC 自己写的图只有合成属性图（1~2 张）；身份池 / 语义槽 / 朝向都是**引用 + 采样规则**，不复制。
4. **纯值 = AC 的常量表**，全屏 fallback，不占通道；覆盖链 `纯值 < object < surface`，**是覆盖不是求和**。
5. **身份按覆盖率加权，语义槽取 surface**；朝向材质不覆盖。
6. **排序按属性合成**：每条属性一条覆盖链，先 resolve 成每像素答案，再给消费者读。
7. **名字在 C# 侧解析一次**，像素里只有 ID 比较；消费者要**登记**自己读了什么，解析不到就报诊断。
8. **AC 的 pass 只有一趟**，服务所有消费者；在 opaque 之后，`{OB, SB} → AC → 下游`。
9. **GTAO 与 AC 无关**（它在 AC 之前，吃不到遮罩）。
10. **导出面冻结**：导出唯一读 **AC 的合成身份池 + manifest**，是 L5 的独立 feature，**不是 AC 的一部分**；编码转换清单登记在案，**实现在 R6 之后**。
11. **AC 只装"三来源压成一个每像素答案"的东西**；新语义一律按 §7 的判据挡回去。
12. **调试与登记是落地的一部分**（V2 §6.1）：没有 debug 视图与登记就不算落地——AC 至少要能看到合成属性图、合成语义槽、消费者登记表、解析失败。
13. **UI 按 `Ho-UI_风格规范.md`**：调试入口在 **`HoAttributeCompositeVolume`**，feature 只放高级设置 + 兜底默认值 + 消费者登记表（只读）。
14. **待定：无。**
