主对话 `01a18a77-70f5-7d61-9ed7-1f3ea070ea4b` 负责 RTShadow 附光接入与冻结姿态的离线采样收敛。本审查处理动作重定向、toe IK / hips / 手指、表情、运镜与音乐同步、人工制作流程。两边不并行修改渲染模块。

## 已有证据的局限

- `Library/HoMmdVideo/*-foot-audit.json` 每支只有 13 个抽样时刻，不能证明整段无跳变。
- 目标 toe IK 在现有重定向器内有意关闭，使用源脚旋转。旧报告所记的目标点误差最高约 0.35 m 是**未驱动控制点与脚尖的距离**，不能直接解释为脚尖位置误差。
- 源/目标脚向量约 12.68° 的差值在所有抽样帧近乎恒定，需与各自静止脚型比较；它不是已经证实的动态翻转。
- 源腿 CCD 自身残差最高约 0.06 m，源姿态也需要交叉核查。仅证明目标 ankle 达到自己的控制点，并不证明控制点位置正确。
- 已有 `production-tests.json` 的 10 项通过只覆盖基础采样、有限配置与部分运镜，不覆盖整段 IK、各腿比例、运行时 MCH/衣物顺序或渲染质量。

## 验证方式

`HoUnityTools/Tests~/MmdMotion/VmdRetargetAudit.cs` 在 `OpenPreviewScene` 中读取影片场景：

- 每 5 个 VMD 源帧记录腿长可达率、源/目标膝角、脚控制点与效应器残差。
- 在不重新捕获 bind pose 的情况下打乱时间点，比较源和目标的骨骼位置/旋转。
- 单独区分“实际非零但未映射”的表情和仅含零键的占位表情。
- 不推进 PlayerLoop、物理、MCH、布料，不保存或重建用户场景。

该测试是骨骼与控制器数据审查，不能代替运行时蒙皮/布料和画面复核。原始报告写入项目 `Library/HoMmdMotionAudit`，本目录保留可阅读结论与汇总。

## 第一轮实际结果

可重算汇总：`python Tools~/MmdStages/MotionAudit-20261031/summarize.py`。输入为本机 Library 中本轮报告，不修改任何 Unity 资产。`summary.json` 保存数值、原始报告及生产源码 SHA256。

### 已修复的两个代码根因

1. **单轴深弯膝被错误折回。** `ClampLocalEuler` 使用 Unity 等价 Euler 分解时，X 超过 90° 可以变成 `(180-X,180,180)`；将 Y/Z 钳回零会改变实际旋转。95° / 120° / 150° 合成链在修复前分别留下约 8.5 / 61.8 / 95.7 cm 的效应器残差。纯单轴且其他轴限制为零时，改用四元数有符号轴角，限制判断与实际钳制共用此语义；复合 Euler 限制保持原逻辑。X/Y/Z、正/负两种方向共 30 个角度测试，最大残差约 **0.0985 mm**。
2. **目标腿重复使用独立 Pole 平滑历史。** 重定向每次已给出完整 FK 与参考膝盖位置，再叠加交互 IK 的旧平面，导致相同帧因访问顺序不同而出现不同目标腿。仅在参考姿态重定向求解前清除此平滑状态；独立拖动 IK 的平滑继续保留。五支影片修复前乱序跳帧最大旋转差 11.6°–143.7°，本轮修复后报告均为 0，位置差也为 0。

原有 `IkPoleValidation` 24 项无失败；原有 `VmdProductionValidation` 的镜头、映射、无外部 Profile 与回退测试共 10 项通过。没有将这些基础回归当作最终蒙皮和画面正确性证明。

### 用户指定 NEMONEMO 的 8–10 秒

第 240–300 源帧、每 0.5 帧测试一次，每侧 121 个样本。原本这段正好包含深弯膝：

| 源腿 | 修复前最坏 ankle 残差 | 修复后本窗口最坏残差 |
| --- | --- | --- |
| 左 | 26.36 cm，帧 274 | 3.17 cm，帧 261 |
| 右 | 25.03 cm，帧 299.5 | 3.51 cm，帧 271 |

**不是已完全解决。** 修复消除了错误角度分解与历史依赖，但源参考腿现有 40 次 CCD 在部分接近伸直的姿态仍有厘米级残差。继续做 Toe / 伸腿优化前应先处理这份源残差，不能挪目标 hips 作为补偿，也不能将“目标 ankle 到达生成目标点”说成正确恢复了原动作。源/目标膝角差仍存在，最大约 19–22°，涉及比例和源求解误差，需要分别定位。

### Sour 独立对照

用本机 Blender 4.5.8 LTS + mmd_tools 4.1.0，无物理，输出 7.5–10.5 秒的 181 个半帧；Unity 读取已有 Sour 姿态 prefab。Blender PMXImporter 实际是 `Vector(v).xzy`，统一到 Ho 坐标使用 `(-x,z,-y)`；`margin=0` 仍须 Blender 帧 `VMD+1`。

**对照没有通过完全一致。** 控制点、脚踝与膝盖仍存在差值（最坏膝盖约 12 cm、脚尖约 9.5 cm；具体骨与时刻见汇总）。这份结果只证明还有独立的导入/求解差异，不能仅凭图形相似或修复后连续就关闭。需要进一步分离 exact key / 插值、完整 Sour append/控制层、原始骨架与 sizing 简化骨架的行为。

### 其他制作缺口

- EX-HAPPY 的成片已经有后期合入的音乐，但保存场景的 Sequence BGM 与 AudioSource Resource 都为空。仅补回这两个引用到该影片已有 `Audio/BGM.wav`，未改灯光、Volume 或原 WTD 场景；preview 重新读取确认音轨约 16.700 秒。
- 有非零关键帧但未映射的表情：EX-HAPPY 16 个、NEMONEMO 11 个、しょ食事タイム 3 个；SWEET-STEP 与 頑張りたい人へ 为零。缺失名称见汇总。不要把只有零关键帧的占位名称与这些实际缺口混在一起，也不凭近似名称猜左右眼/嘴方向。
- 手部仍需要用局部指节轴与实际蒙皮独立复核；“公式算出的期望旋转等于同公式设置的旋转”不是足够的手指正确性证据。
- 当前 preview scene 审查不执行运行时合骨架、HoAux、MCH 和衣物；这些交互与最终成片仍需运行时指定片段复查。RTShadow/采样收敛归主对话，本审查没有改这些模块或共享 Renderer。
